# APEX

Свой инструмент кросс-постинга видео в **YouTube Shorts, Instagram Reels и TikTok** (и Facebook-Страницы при бизнес-верификации) из одного окна.
Один сервер, друзья входят через браузер и подключают свои аккаунты. Безопасность — приоритет:
доступы к соцсетям хранятся в зашифрованном виде, вход без паролей (magic-link).

> Название — **APEX**. Внешние приложения в консолях Google, Meta и TikTok можно переименовать там же, на работу это не влияет.

## Что это умеет (цель)

- Загрузил видео + написал текст один раз → публикация во все выбранные сети.
- Отдельный статус по каждой сети, повтор при ошибке, расписание публикаций.
- Закрытый доступ только для приглашённых друзей (инвайт-коды).

## Честные ограничения площадок (это не баг инструмента)

| Сеть | Статус на старте |
|------|------------------|
| Instagram | Полная публикация Reels (вход через Instagram, профессиональный аккаунт). Для друзей — роль тестировщика; для всех — App Review. |
| YouTube | Полная публикация Shorts. По умолчанию ~6 загрузок/день, пока не пройдён quota-аудит Google. |
| TikTok | Видео приходит **во входящие приложения** — публикация одним нажатием, текст вставляется там же. Прямая публикация — после аудита TikTok. |
| Facebook | Выключено по умолчанию (`META_ENABLE_FACEBOOK=1`): нужна бизнес-верификация Meta. |

## Качество видео

Загруженный файл — **мастер**, он никогда не перекодируется. Под каждую сеть воркер
готовит отдельную версию (`src/lib/video.ts`, `src/lib/renditions.ts`):

| Сеть | Что уходит |
|------|-----------|
| YouTube | Оригинал байт в байт (HEVC, HDR, 4K, 60 fps), resumable-загрузка частями по 32 МБ. |
| TikTok | Если кодек/fps/размер подходят — перепаковка в MP4 **без перекодирования**. Иначе H.264 CRF 16 в исходном разрешении (до 4K), HDR → SDR, >60 fps → 60. |
| Instagram | Если подходит спецификации Reels — перепаковка без потерь. Иначе H.264 High CRF 17 (preset slow), короткая сторона 1080, ≤24 Мбит/с с учётом лимита 300 МБ, закрытый GOP 2 с, AAC 48 кГц, faststart, без edit list. |

После кодирования файл проверяется ffprobe против правил сети, прежде чем уйти в публикацию.
Тестовый прогон без отправки в сети: `PUBLISH_DRY_RUN=1` для воркера.

## Установка у себя

Этот репозиторий не содержит ничьих доступов. Чтобы инструмент заработал,
нужно завести **свои** приложения в кабинетах площадок и подключить **свои**
аккаунты — чужие подключить невозможно.

### Что нужно получить самому

| Где | Что завести | Зачем |
|-----|-------------|-------|
| [Google Cloud Console](https://console.cloud.google.com) | OAuth-ключи + YouTube Data API v3 | публикация Shorts |
| [Meta for Developers](https://developers.facebook.com) | приложение Instagram с входом через Instagram | публикация Reels |
| [TikTok for Developers](https://developers.tiktok.com) | приложение + Content Posting API | загрузка во входящие TikTok |
| Telegram | бот у [@BotFather](https://t.me/BotFather) | видео в канал и истории |

Пошагово — в папке [docs/](docs/). Площадки требуют адрес с HTTPS и ссылки на
политику конфиденциальности и условия: обе страницы уже есть в приложении
(`/privacy` и `/terms`).

### Запуск

```bash
cp .env.example .env
npm run keygen     # три разных ключа шифрования — вставьте их в .env
```

Заполните в `.env`: `APP_URL`, `OWNER_EMAIL` (станет владельцем),
`POSTGRES_PASSWORD` и ключи тех площадок, которые нужны. Затем:

```bash
docker compose up -d
npm run doctor     # проверит, что всё на месте
```

Откройте `APP_URL`, войдите по ссылке на почту и подключите аккаунты на
странице «Аккаунты».

### Безопасность доступов

- `.env` и папка `media/` закрыты в `.gitignore` — в репозиторий они не попадут.
- Токены соцсетей лежат в **вашей** базе, зашифрованные AES-256-GCM ключом из
  **вашего** `.env`. Без этого ключа база бесполезна.
- Приложение не запустится, если ключи короче 32 байт, однообразны или совпадают
  друг с другом.
- Вход закрытый: новый человек попадает внутрь только по инвайт-коду от владельца.
- Файлы подтверждения домена площадок (`public/tiktok*.txt`) тоже не коммитятся —
  они привязаны к конкретному кабинету разработчика.

## Стек

TypeScript / Next.js + фоновый воркер (BullMQ) + PostgreSQL + Redis + Caddy (авто-HTTPS),
всё в Docker. Запуск сводится к одной команде.

## Настройки публикации по сетям

Описаны одной таблицей в `src/lib/publish-settings.ts`, форма в композере
строится из неё. Добавить поле — дописать строку, а не верстать ещё одну форму.

| Сеть | Что можно задать |
|------|------------------|
| YouTube | доступ (по умолчанию **публично**), категория, уведомлять подписчиков, видео для детей |
| Instagram | показывать Reels в ленте профиля |
| TikTok | приватность, комментарии, дуэты, сшивки, метки «создано ИИ» и «коммерческое» — применятся при переходе на прямую публикацию |
| Telegram | срок жизни истории (6 ч / 12 ч / сутки / двое суток), оставлять ли её в профиле, беззвучное уведомление в канал |

## Telegram

Подключается не через OAuth, а токеном бота: заведите бота у @BotFather и
вставьте токен на странице «Аккаунты». Два вида назначения, и они считаются
разными аккаунтами:

- **Канал** — бот должен быть в нём администратором с правом публикации.
  Bot API принимает загрузку до 50 МБ, поэтому длинное видео сжимается.
- **Истории** — требуют, чтобы бот был подключён в Telegram: Настройки →
  Telegram для бизнеса → Чат-боты, с правом «Управление историями». Раздел
  «Для бизнеса» доступен только с подпиской **Telegram Premium** — это
  требование Telegram, обойти его нельзя.

Требования к видео для истории заданы площадкой жёстко, и мы приводим файл
к ним сами: ровно 720×1280, кодек H.265, ключевой кадр каждую секунду,
не длиннее 60 секунд и не тяжелее 30 МБ. Кадр обрезается по центру, чтобы не
было чёрных полей. Подпись к видео в канале — до 1024 символов.

## Обложка

Кадр выбирается ползунком или из пяти автоматических кандидатов (10/30/50/70/90 %
длительности). Браузер снимает кадры только для показа; в сеть уходит миллисекунда,
а сам кадр отрисовывает ffmpeg из исходника в полном качестве. Instagram получает
его как `thumb_offset`, YouTube — загруженной картинкой. Если YouTube обложку не
принял, публикация не отменяется: видео уже вышло, а о неудаче сказано в карточке.
TikTok при загрузке во входящие обложку не принимает.

## Если что-то не работает

```bash
npm run doctor
```

Читает настройки и проверяет: ключи в `.env`, связь с базой и Redis, наличие
ffmpeg с нужными кодировщиками, права на папку с видео и свободное место,
живость обработчика публикаций, сроки доступов к сетям и доступность сайта по
публичному адресу (по нему Instagram забирает видео). Ничего не меняет и никуда
не публикует; у каждой находки написано, что сделать. В кабинете то же самое
видно баннером, если обработчик не отвечает.

Тесты логики выбора версии видео и лимитов текста:

```bash
npm test
```

## Статус

Работает: вход по ссылке и инвайты, подключение YouTube / Instagram / TikTok, композер
с проверкой лимитов текста и видео, версии видео под каждую сеть, расписание, статусы
с прогрессом, безопасные повторы, уборка файлов (`MEDIA_RETENTION_DAYS`, по умолчанию 7).
